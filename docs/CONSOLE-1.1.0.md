# 控制台 v1.1.0 更新与验收

本版针对用户反馈的三条路径：重复进入页面需整页等待、空调伴侣偶发查询超时、设备已动作而卡片仍长时间“执行中”。保持三台设备映射、凭据位置、MCP 进程和语音插件不变。

## 最终行为

- `GET /mijia-console/state` 只返回内存快照与卡片配置，首次也不等待云端。前端内存保留上次面板内容，重新进入立即显示，后台再查询。
- `GET /mijia-console/device?alias=...&section=state|stats` 分设备、分当前状态/用电统计更新。任一慢请求不阻塞其他卡片，统计不阻塞开关状态。
- 默认可见时自动刷新：每轮请求完成后间隔 10 秒再开始；可关闭，已有用户设置保留。Host 当前状态 TTL 10 秒，统计 TTL 5 分钟，手动刷新强制查询；同一设备/环节/有效代次的在途请求合并。日统计跨北京时间日期强制失效。
- 状态或统计失败保留各自上次成功数值与时间，错误按卡片展示。首次无数据用 `--`，非有限或非法用电数值不会显示为 NaN，也不会把空值当作零。
- 点击开关立即展示目标位置，同时显示“正在发送”。接口接收后解除发送忙碌，改为“指令已发送，正在确认状态”，Host 做一次独立的有时限回读。
- 回读与目标属性一致才标为“回读一致”；不一致继续标为待确认，绝不自动重复发送。空调伴侣回读和功率只作为可观测信息，不作为所有模式下空调本体已执行的保证。
- 前后端均阻止同设备重复发送；Host 代次隔离旧回读，Client 按每设备 revision 与 Host epoch 合并响应，旧快照不会覆盖新操作。
- 语音/聊天操作记录保留，并使对应设备状态缓存失效；页面可见的后续查询获取新状态，不在页面隐藏时持续轮询。

## 超时和生命周期

读取单次 15 秒，上次隐式“15 秒 + 再试一次”已移除，后续可见刷新或用户重试负责恢复。写入 30 秒且从不自动重发。Client 读请求 20 秒、控制请求 35 秒上限。MCP 返回 `isError` 会当作错误，不能继续记为成功。

写超时可能已经产生实际动作，记录“结果待确认”，只尝试读取状态。工具适配器即使忽略 AbortSignal，Host 也会结束等待；无法保证取消已经发送到云端的动作。

离开页面取消前端读请求，清理监听器与刷新定时器；Host 已开始的共享读取最多继续到本次时限。已发送控制及一次回读不因页面切换被撤销。禁用控制台插件中止其在途等待，不停止共享 MCP 进程。没有新增后台常驻轮询。

缓存仅在内存中：面板切换保留，Host 重载/应用重启后重新查询。页面展示的是带时间戳的云端查询结果，不承诺设备主动推送或零延迟同步。

## 验证证据

执行 `npm ci`、`npm run check`、`npm test`（Node.js 22+）。本轮 26 项测试通过：20 项真实 Host 路由/Client 合并与数值测试，6 项真实 React 渲染器的挂载、事件与卸载测试；传输、计时器和物理设备采用受控桩。

覆盖：立即快照、分批加载、缓存/合并请求、失败保留旧值、慢回读不阻塞发送响应、双击只写一次、回读不一致不报确认、MCP 工具错误、两类迟到结果、写超时不重发、语音/聊天失效、路由鉴权、白名单与范围、插件停用取消、Host 重启代次、NaN、面板切换/隐藏与定时器回收、发送连接中断后的不确定结果提示。

**未验证**：用户本机 Harness 的真实渲染与热更新、实际米家网络时延、物理设备动作、浅色/深色及窄窗口。没有调用真实米家设备；不能将自动测试结果标为实机验收通过。

## 本机更新

1. 拉取本仓库最新代码。若 Harness 安装时复制了 bundle，需将更新后的 `bundles/mijia-console` 更新/重新安装到原插件位置；仅更新 Git 工作副本不会自动更新另一个安装副本。
2. 保留自己的 `cordis.patch.yml` 设备配置。本版不改 DID、属性名、范围、凭据或 `mijia-mcp` 配置。
3. 在 Harness 中禁用再启用 `include:mijia-console` 使 Host 更新；重新加载客户端/应用，使 `client.js` 也更新。仅重载 Host 不能保证 Client 模块缓存更新。
4. 确认控制台插件版本 1.1.0，再测下面的路径。

## 实机验收

- 首次进入：三张卡片先显示，属性和统计分别更新；某设备超时不拖住另外两台。
- 离开再进入：先保留上次卡片与值，不再空白等整批云端结果；时间戳标明数据新鲜度。
- 灯带/挂灯开关：点击立即有发送反馈，接口接收后解除忙碌，即使回读还在等待；双击不重复写入。
- 查询异常：上次数据仍在，单卡显示超时和重试；无 NaN；恢复后错误清除。
- 操作与刷新交错：旧刷新/旧回读不能把开关或温度跳回旧值；超时后先查询，不盲目重发。
- 离开/隐藏页面：不再发起周期查询；返回继续更新。语音控制仍可独立工作。
- 空调伴侣：区分接口接收、目标属性回读和物理空调动作，模式/风速/温度仍需用户真实验证。

## 耗时诊断

Host 标准日志中的 `[mijia-console]` 事件记录 `mcp.finish`（工具、结果、耗时）与 `control.finish`（设备别名、发送耗时）。不记录密钥、账号凭据、DID、调用参数值或返回正文。可对比写入接收与查询耗时，定位云端、MCP 或回读链路；测试桩耗时不能作为真实设备性能数据。
