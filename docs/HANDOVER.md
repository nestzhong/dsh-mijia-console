## 2. 接入结构与执行层限制

- 工具命名 `mcp__mijia__*`，共 14 个；调用超时 90s；启动失败即报错；自动重连开启
- `mijia-device-guard` 用 `tools.guard` 在执行前拦截（已实测）：
  - 白名单外 did/设备名 → 拒绝（实测：宠物喂食器 did 被拒 ✅）
  - `run_scene` / `run_speaker_command` / `speaker_play` → 一律拒绝（可绕过白名单，实测 ✅）
  - `toggle` 动作 → 拒绝（白名单内同样拦截，实测 ✅，要求显式 on=true/false）
  - `login`/`login_status`/`list_*`/`get_device_spec` → 放行（实测 ✅）
  - 未知 `mcp__mijia__*` 工具 → fail-closed 拒绝
- 系统提示词已注入别名 ↔ did 对照与操作规范（超时不盲重试、标注单位/新鲜度、空调伴侣"已发送≠已执行"）
- 与现有语音助手 `@local/voice-conversation` v1.8.0 零改动、零冲突；语音入口走同一聊天通道复用同一套工具

## 3. 启停方式（按需运行）

- **启动**：bundle 启用状态下，MCP server 随 Harness 插件激活时拉起；无定时轮询，仅在收到查询/控制指令时请求云端
- **停止**：插件管理中禁用 `include:mijia-api` 行（或整个 `@local/mijia-mcp` bundle）→ Harness 回收 stdio 子进程；重新启用即恢复（配置改动用"禁用/启用"对应行即可热生效，已实测）
- **自动退出**：无独立空闲自动退出机制（如实说明）；进程随插件生命周期存在

## 7. 复现/维护

- 重装：`uv pip install --python ~/.local/share/mijia-api/venv/bin/python "mijiaAPI[mcp]"`
- 重新登录：`mcp__mijia__login`（会话内）或 `~/.local/share/mijia-api/venv/bin/mijiaAPI login`（CLI）
- 修改白名单：编辑 `mijia-mcp/cordis.patch.yml` 的 `devices` 列表 → 对 `include:mijia-device-guard` 做一次禁用/启用
